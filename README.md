# Telegram 古诗词抽奖机器人

基于 Python 3.11+、aiogram 3、SQLAlchemy、SQLite 和 APScheduler，界面仅支持简体中文。

## 报名规则

1. 用户先私聊机器人发送 `/start`，然后点击频道抽奖帖的「参加」。
2. 机器人私聊发送一道古诗词题：诗句留出两个字，提供四个双字选项。
3. 选择正确答案即自动完成本场报名，无需再次点击参加。报名时仍会检查必加频道、必加群组、黑名单和开奖条件，频道与群组必须全部加入。
4. 每题限时 **60 秒**，超时自动计一次错误并结束本题，准备好后点击「继续答题」获取新题。正常答错会扣除一次机会并自动更换题目；每人每场最多答错五次。第五次答错后无法参与这场抽奖，其他抽奖单独计数。
5. 内置 25 道题，同一用户跨场次随机轮换，25 道用完前不重复；下一轮首题不会和上一轮末题相同。重复点击参加只重发当前题，不提供免费换题，也不延长当前时限。
6. 题目、选项、错题次数、题目截止时间、轮换进度和一次性按钮凭据保存在数据库中。重启不会恢复机会或重置60秒时限，已超时题目会自动补计一次错误，旧题按钮无法再次作答，转发题目无法代替别人报名。

题库位于 `bot/poetry.py`，共25题，固定编号，请勿自行修改已保留题目的编号或答案。升级时会清理轮换记录中的退休编号；旧版尚未超时的退休题目会免费换题，不扣已有机会；已超时则沿用正常计错规则。每题包含作品、作者、填空诗句、一个答案及三个干扰项。

古诗词答题用于增加自动报名的成本；公开固定题库无法阻止掌握题库或使用语言模型的脚本，不能视为绝对防脚本措施。

## 频道与群组及命名邀请链接

创建时分别填写必加频道和群组，每行一处，并给链接命名：

```text
官方频道 | https://t.me/你的频道名
交流群 | https://t.me/你的群组名
```

私有邀请链接需附上对应的负数编号，机器人通过编号检查成员资格和发布消息：

```text
会员交流群 | https://t.me/+你的邀请链接 | -1001234567890
```

帖子、确认页和未加入提示只显示可点击的「官方频道」「交流群」等名称，不把长邀请链接作为正文展示。私有邀请链接本身不能被Bot API解析为群组编号，因此不能省略编号。仍兼容旧版 `@用户名` 及 `编号 | 邀请链接` 格式。

用户须加入所有列出的频道和群组，提交答案时会再次校验。机器人须为各处管理员，并具有频道发布消息权限。频道和群组至少填一处。

## 奖品数量核对与全部重录

录入奖品后，机器人会先显示识别数量和计划中奖人数，核对后再确认：

- 独立码一行一条，自动去掉空行、首尾空白和本档重复内容。可以分多条消息粘贴，系统累计统计；计数和实际入库使用同一套规则。
- 共享文本整段算一份，保留内部换行。重新发送文本会替换本档待确认内容，不按行拆成多个奖品。
- 每档录完后点击「确认本档奖品」，才进入下一档；数量不足或超出会明确显示，但不擅自更改已设置的中奖人数。
- 数量不对时点击「全部删除并重新添加」，或发送同名文字，会清空本场草稿中所有档位的奖品内容，从第一档重新录入；标题、频道、群组、开奖条件和计划中奖人数保留。最终发布确认页也提供同一按钮，并逐项汇总数量。
- 新抽奖和已确认奖品在同一数据库事务中保存；保存失败不发布，保留草稿供重试。

使用 `/addcodes` 补货时也先显示本次识别数量，点击「确认入库」才写入奖池。补货的清空按钮只清空本次尚未确认的内容，不删除已有库存或领取记录。继续粘贴会更新计数，旧按钮自动失效，重复点击不会重复入库。

## 自动发布

不再询问「发布到哪里」。录入奖品后直接确认，机器人自动把同一场抽奖发布到上述全部频道和群组，按真实聊天编号去重。各处按钮共用同一份报名名单，用户不会因从不同帖子参加而获得多个名额。开奖及重抽公告回复到所有已发布的抽奖帖，中奖私信每人仍只发一份。

每处发布结果独立持久化。部分位置失败时会提示失败名称；修复权限后发送 `/republish 抽奖编号`，只补发尚未成功记录的位置。全部发布失败则取消该场。发布过程中暂不接受报名，防止满人数模式在其余帖子尚未发完时提前开奖；重启会恢复中断的发布。若Telegram已接收消息、但进程在记下消息编号前崩溃，恢复时仍可能出现重复帖子。

## 开奖条件

创建向导的「开奖条件」支持以下格式：

| 输入示例 | 行为 |
| --- | --- |
| `30m`、`6h`、`2026-12-01 20:00` | 到指定时间开奖，具体时间使用配置的时区，默认北京时间 |
| `满100人` | 100名不同用户答题通过并成功报名后立即开奖，不设时间截止 |
| `6h或满100人` | 到时间或满人数，任一先到即开奖 |

点击参加、尚未答对、未验证或已被拉黑的记录不计入满人条件。最后一人的报名、关闭抽奖和写入中奖名单在同一事务中完成，并发点击不会超额报名或重复开奖。

60秒截止时间和题目状态保存在数据库，由单个后台任务每秒批量检查；即使后台尚未扫描，提交超时答案也会即时计错，不能报名。超时后不自动连续发题，不会因用户离开就连续扣完五次机会。程序重启会恢复截止时间并补计超时，重复检查不会重复扣机会。旧版本已发出的题目在首次升级时获得一次60秒过渡期，之后重启不重置。

## 部署

```bash
git clone https://github.com/hikling/tg-giveaway-bot.git
cd tg-giveaway-bot
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# 编辑 .env，填写 BOT_TOKEN 和 ADMIN_IDS
python -m bot
```

默认使用长轮询，不需要域名、公网验证页面或 Cloudflare 配置。Webhook 可选，配置 `WEBHOOK_BASE_URL` 时必须同时设置至少 8 位的 `WEBHOOK_SECRET`。Docker 部署参见 `deploy/README.md`。

升级前停止旧实例并备份 `data/` 和 `.env`；更新代码、安装依赖后启动。启动时自动创建答题和多处发布记录表，并补充群组、开奖条件、发布状态和题目截止时间字段，保留旧抽奖、报名及领奖数据。旧 Turnstile 配置不再使用，历史抽奖也统一使用古诗词答题；已报名用户无需重答。历史数据库中旧验证相关列保留用于兼容，不再参与认证。`DEFAULT_LANG=en` 等历史设置会自动归一为中文。

## Telegram 管理员小程序

设置 `MINI_APP_BASE_URL=https://giveaway.example.com` 并重启后，现有管理员可在机器人私聊菜单点「抽奖管理」。首次私聊的管理员先点 Telegram 自带的「开始」按钮。小程序复用当前抽奖库，可创建和预览抽奖、核对奖品数量、补货、补发、重抽，以及管理黑名单和管理员。

小程序需要 Telegram 客户端可访问的 HTTPS 地址。长轮询仍可用于接收机器人消息。管理员命令和参与者的报名、答题及领奖流程仍可照常使用。[HTTPS 配置](deploy/README.md#管理员小程序)

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/start`、`/help` | 欢迎与帮助 |
| `/me` | 近期报名记录 |
| `/newgiveaway` | 管理员创建抽奖，确认时发送「确认」 |
| `/list`、`/cancel <编号>` | 查看、取消抽奖 |
| `/reroll <编号> <奖项名>` | 对已结束抽奖重抽 |
| `/retry <编号>` | 补发失败的中奖私信 |
| `/republish <编号>` | 只补发未成功发布的抽奖帖 |
| `/ban <用户编号> [原因]`、`/unban <用户编号>` | 黑名单管理 |
| `/addadmin <用户编号>`、`/admins` | 管理员管理 |
| `/gate [抽奖编号]` | 查看附加编号门槛及报名分布 |
| `/addcodes <编号> <奖项名>`、`/prizestatus <编号>` | 补货、查看奖池 |
| `/claim <编号>`、`/myprizes` | 领取、回看奖品 |

报名和答题只确认参与资格。开奖后，机器人向中奖者发送通知，奖品内容由当前中奖者领取时单独发往私聊。`/myprizes` 只在机器人私聊里显示领取记录，`/newgiveaway` 和 `/addcodes` 也请在私聊或管理员小程序使用。

独立码在同一场抽奖中只会发放一次，补货时会跳过奖池里已有的独立码。共享文本仍可由所有中奖者领取，也可以由主办方自行联系发奖。奖项已有奖品被领取后无法重抽。开奖、重抽和领奖均使用数据库事务，失败的中奖通知可补发。机器人必须是每个必加频道和必加群组的管理员，才能可靠检查成员状态。

## 可验证开奖

发布时公布 `sha256(seed)`，开奖时揭示种子、轮次及参与者摘要。先排除黑名单，再按奖项顺序排除之前已中奖的用户，将剩余用户按编号升序排列，调用 `bot.utils.antiabuse.draw_indices(f"{seed}|{奖项名}", 人数, 名额)`。重抽使用 `f"{seed}|{奖项名}|r{轮次}"`，排除重抽前所有当前中奖者。重放需要对应时刻的参与者名单及排除名单；摘要本身不能恢复名单。
